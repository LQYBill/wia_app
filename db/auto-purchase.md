# 自动缺货采购任务

先执行 `db/增量SQL/20261117_auto_purchase.sql`，再部署代码。迁移不会自动开启任何 SKU，也不会创建或启用线上任务。

在现有 Quartz 定时任务管理中配置：

- 任务类：`org.jeecg.modules.business.domain.job.AutoPurchaseJob`
- 每日 09:00 的 Cron 示例：`0 0 9 * * ?`（执行时间沿用现有 Quartz 调度时区）。
- 任务参数示例：

```json
{
  "clients": {
    "CLIENT_A": {
      "email": "purchase-a@example.com",
      "mabangUsername": "buyer_a",
      "autoMarkPaid": true
    },
    "CLIENT_B": {
      "email": "purchase-b@example.com",
      "mabangUsername": "buyer_b",
      "autoMarkPaid": false
    }
  },
  "timezone": "Europe/Paris"
}
```

`clients` 必填，以客户 `internal_code` 为键，同时作为客户白名单。所有客户代码必须存在。每个客户独立配置 `email`（必填发票收件邮箱，不回退到客户档案邮箱）、`mabangUsername`（必填马帮采购计划操作人）和 `autoMarkPaid`（只接受 JSON 布尔值，省略时该客户默认为 `false`）。开启付款标记后把该客户采购票 `paid_amount` 设置为 `final_amount`，不产生余额扣款或外部转账。顶层不再接受原来的 `clientEmails`、`mabangUsername`、`autoMarkPaid` 配置，需按示例迁移到各客户内部。`timezone` 决定每日防重的日期边界，默认巴黎，与 Quartz 的执行时区是两个配置。

SKU 编辑接口 `/sku/edit` 的请求字段 `autoPurchaseEnabled` 对应数据库 `sku.auto_purchase_enabled`，默认关闭。SKU 新增、查询、导入导出 DTO 也包含此字段；本仓库未提供后台 SKU 编辑页面，需要前端展示开关时使用该字段。

`MabangSkuSyncJob` 的日期增量和指定 SKU 两种同步方式均请求 `showLabel=1`。同步结果中 `label`（兼容 `labelData`）包含名称精确为“缺货采购”的标签时，将对应数据库 SKU 的 `auto_purchase_enabled` 标记为 `1`，即使其他 SKU 字段没有变化也会保存；标签 SKU 不受同步流原有销售状态过滤限制。没有该标签、标签为空或被移除时不自动清零。自动采购本身仍按下述正常销售等条件筛选。

同步任务默认只覆盖最近 5 天更新的 SKU。部署后若需首次覆盖历史标签，可在该任务指定完整日期范围，或用 `{"skus":["PS46000013-FC"]}` 对指定 SKU 执行同步；任务不新增数据库中不存在的 SKU。

`MabangSkuStockUpdateJob` 也会在库存更新后拉取“缺货采购”标签：使用该次库存任务的完整 SKU 范围，按每批最多 50 个 SKU 请求资料接口并携带 `showLabel=1`，仅将命中标签的数据库记录标记为 `auto_purchase_enabled=1`。即使库存数量没有变化仍会同步标签。默认覆盖所有启用客户关联的 SKU，不受最近 5 天日期窗口限制；配置 `clients` 或 `skus` 时，标签与库存使用相同筛选范围。无标签 SKU 保留原标记，此步骤不更新其他资料或新建 SKU。无需新增任务参数。

库存任务在调用两个马帮接口前，统一按本地数据库状态排除“停止销售”（`status=5`）的 SKU，并去重和剔除空代码；默认全量、指定客户、指定 SKU 均执行此过滤。状态检查采用每批最多 1000 个代码的数据库查询，不为检查状态额外请求马帮。其余状态继续沿用现有同步范围；过滤后为空时不调用库存或标签接口。此过滤不修改 SKU 状态或已有自动采购标记。停止销售的 SKU 若重新上架，需要先由 SKU 资料同步任务更新本地状态，随后库存任务会重新纳入。

SKU 分页遇到成功响应的空列表或 `data=null` 时正常结束，并保留此前页读取的 SKU；缺失下一页游标也结束遍历。非 `200` 响应、请求无响应或游标重复会明确报错，不将接口错误当成成功的空结果，也不会因此清空既有自动采购标记。

任务仅处理白名单内启用客户（`active=1`）关联的正常销售 SKU（`status=3`）、非赠品（`is_gift=2`），并要求 SKU 已开启自动采购。多个客户共同关联同一 SKU 时跳过该 SKU，因为其库存不能按客户独立分配。

缺口数量为 `max(未发货订单需求 - 宝安仓实时库存 - 实时采购在途, 0)`。订单需求沿用库存报表口径：订单和明细 `erp_status` 都为 1 或 2。库存通过现有马帮库存接口实时读取，不依赖本地库存同步完成；任一候选 SKU 返回缺失、仓库缺失或数量缺失时，该客户本次不开新票。按实际缺口采购，不增加安全库存或按 MOQ 向上取整。没有缺口时不开票。

每个客户每天最多一张自动采购票，合并本次所有符合条件的缺货 SKU。沿用现有采购定价、促销、币种及小额采购国内运费规则；使用客户默认开票主体。票据和任务记录在同一事务中提交，付款标记按参数同步保存。生成 XLSX 发票及独立的 `_purchase_details.xlsx` 采购明细后，在同一封邮件中发送两个附件，再按供应商创建马帮采购计划，即使 `autoMarkPaid=false` 也会创建采购计划。明细直接读取已保存采购票的 SKU、英文名称、数量、欧元商品单价和促销前商品金额，不重新计算当前价格；明细金额不含促销扣减及国内运费，最终应付金额和支付币种以发票为准。任一附件生成失败时，任务保持可重试，不发送缺少附件的邮件。邮件服务保留现有发件账号抄送逻辑。

## 重试与核对

后台任务通过 `makeAutomaticInvoice(purchaseId, clientId)` 生成发票文件，校验票据所属客户，不依赖 Quartz 线程中的 Shiro 登录上下文；网页开票继续使用原有权限检查。若文件生成失败，已保存的采购票和付款标记保留，任务回到 `READY` 后重试复用原票。

`auto_purchase_run` 保留客户、日期、票据、收件地址、付款参数、马帮操作人、邮件结果及计划结果。重试沿用首次保存的配置，不重新开票。客户行锁、客户日期唯一约束和计划状态原子抢占共同防止多个任务同时处理。

- `READY`：可重试。邮件或文件生成失败会回到此状态，下一次执行优先恢复旧票。已记录邮件成功时不重发。
- `SENDING`：正在处理；若进程崩溃后停留此状态，需要核对外部结果。
- `DONE`：马帮全部供应商采购计划创建成功；`plan_result` 保存返回的采购计划分组 ID。当日重跑跳过，次日读取实时在途库存重新计算缺口。
- `UNKNOWN`：接口异常、失败或部分成功，需要根据发票号和 `plan_result` 核对马帮。该客户后续任务报错并暂停新票，其他客户继续执行。不会自动重试可能已成功的采购计划。

人工核对时，若所有计划已存在，应补齐采购票 `ordered`、`group_id` 等既有字段，并将任务置为 `DONE`。若确认所有外部计划均未创建或已撤销，且采购票仍有效且未标记 ordered，可将任务置为 `READY` 重试。部分成功应先人工完成或撤销已有计划，不可直接重置状态。取消自动采购票同样需核对并处理任务记录。

邮件发送与数据库不是同一事务：若 SMTP 已接受邮件后进程退出、但成功标记尚未保存，恢复时可能重复发邮件。马帮请求后的不确定状态会阻止自动重发采购请求。

客户条件当前明确采用任务白名单和启用状态；上线前应按业务确认名单、时刻、SKU 开关、采购员及付款标记参数。
